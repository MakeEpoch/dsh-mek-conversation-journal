# 对话整理 · Conversation Journal

DSH 插件：读取 Host 本机的 DSH 与 Codex 对话，整理成日报与知识库。结果保存在本机，可选择同步到 Notion。

入口：**设置 → 对话整理**，内部提供「整理」「内容库」「设置」三个入口。手动整理、历史日期补生成、来源回查和 Markdown 导出在前两个入口完成；模型、来源、自动计划与 Notion 连接集中在「设置」。自动整理默认关闭。

## 安装与配置

要求：DSH `>=0.2.1-rc.2 <0.3.0`，Host 的 Node.js `>=22.16`，启用 DSH 的 `llm` 模型服务；选择 DSH 来源时还需要 `sessionQuery`。插件通过公开服务读取历史，不激活旧会话、不修改原始聊天。

从源码构建：

```sh
cd dsh-plugin-conversation-journal
npm install
npm run build
npm test
npm pack --pack-destination artifacts
```

交付包已经包含 `lib/client.js`；使用安装包不需要在宿主运行构建。通过 DSH 插件管理器安装本地安装包，或在工作区运行以下带校验与备份的安装器：

```sh
node scripts/install-web.mjs --dry-run
npm run install:dsh:web
```

安装器仅支持现有 Web profile，备份配置后使用 DSH 官方插件管理器安装，不自动重启服务。安装后重启对应的 DSH Web 进程并刷新浏览器。在 Desktop 使用时通过它自己的插件管理器安装，不能把 Web 安装回执当成 Desktop 激活证据。

首次使用：

1. 打开 **设置 → 对话整理 → 设置 → 来源与模型**，选择 DSH、Codex 对话来源。从 DSH 已配置的模型列表中选择总结模型；列表暂不可用时可以手动填写提供商和模型 ID。整理会使用该模型的额度或费用，不调用 Codex 来做总结。
2. 核对日报时区；选择 Codex 时还需核对数据目录。默认值为 `Asia/Shanghai` 和 `~/.codex`，目录属于运行 Host 的电脑。目录不可读或 DSH 会话查询服务不可用时，页面会提示检查来源。
3. 在底部保存栏点击「保存设置」。仅提交已改动的配置字段；错误显示在对应输入旁。切换插件内部入口会保留当前草稿，尚未保存的修改不会自动生效。
4. 回到「整理」，选择日期和内容类型，点击「开始整理」。默认整理日报与知识库，也可以单独选择一种。有配置草稿时，按钮为「保存并开始整理」，配置通过校验并确认生效后才会启动任务。选择历史日期本身不会改写配置。
5. 在「内容库」搜索全部已整理内容，按日报或知识库筛选、翻页、查看正文与来源；详情中可复制正文或导出 Markdown。最近七天的条数来自本地已采集记录，不能据此认定原始来源没有新对话。

Notion 为可选配置：进入 **设置 → 对话整理 → 设置 → Notion 同步**，开启同步，填写内部连接 Token 与目标父页面。可展开说明创建连接，并在 Notion 目标页面为该连接授予读取、插入、更新内容权限。点击「保存并连接 Notion」会先保存配置，再检查连接并建立「对话日报」「对话知识库」两个数据库；已保存配置时按钮为「连接并准备数据库」或「检查目标数据库」。Token 不回显，留空保留原值。

Notion 未连接时仍可在本机整理。连接后点击「补传内容」同步已有结果；有未保存修改时对应按钮会先保存再补传。未同步数统计整个索引；同步状态按当前目标页面及内容回执核对，换目标后会重新建立该目标的同步关系。

需要定时运行时，在插件「设置 → 自动整理」开启「每天自动整理」并保存。排除项目、会话及模型预算位于「设置 → 隐私与高级」。

## 生成规则

- 日期按每条消息的实际时间计算，不按会话文件夹或会话创建日期计算；跨天会话分别整理。
- 日报每天一份。知识按规范化标题与项目定位；匹配不确定时保留独立知识，不凭相似标题强行合并。
- 普通聊天只需要时间、发言者、正文、来源引用，不要求有项目、工具调用或任务状态。
- 知识保留来源、日期与适用条件。模型被要求区分讨论、实际执行和已验证事实；引用 ID 会在本地校验，但内容语义仍需使用者审阅。
- Codex 增量读取 `sessions` 和 `archived_sessions`，保留完整行的读取游标；未写完的末行下次再读。新的消息采集会跳过 `analysis` 等非用户可见频道，保留正文、用户可见的回复及工具调用和结果；系统角色和账户元数据不作为对话正文采集。此规则不代表旧版本已缓存内容已完成清理，见下文的缓存边界。
- DSH 使用公开的 `sessionQuery`，跳过已识别的继承历史、合成用户消息与压缩替换消息。插件总结直接调用模型服务，不创建总结会话，因此不会把自己的总结循环采集。
- 同一来源按稳定消息标识去重；不同来源只归并同项目中完全相同的较长内容。没有来源关联的转述、语义重复不保证自动识别。
- 长对话分批分析并缓存；有多批时再合并日报。不会静默截掉超预算内容：超过批次或合并预算会报错并保留旧结果。单次最多 40 批；单条超过 2MB 的 Codex 记录会跳过并显示采集提示。
- 超过 8000 字符的工具调用和输出会先在本地压缩，保留首尾、部分错误/测试/退出码与改动文件线索，并明确标记为不完整输出；原始内容通过来源回查。这降低代码和大段日志带来的模型用量，不影响普通聊天正文。
- 排除项目或会话影响后续采集与生成；旧知识作为模型参考时同样检查来源、排除项目和会话。之前已有的本地缓存或 Notion 页面不会自动删除。

每日自动生成按设定时间整理当天；翌日再次整理前一天以补入截止时间后的对话。Host 离线恢复时补最近一天，较早日期用手动补生成。每个时间段最多自动尝试一次；失败可手动重试。生成结果在相应的来源记录发生变化时重新分析，已成功的分批结果会复用。

## Notion 更新与人工编辑

- 日报通过稳定日期 Key 查找，知识通过知识 Key 查找，重跑更新原页面。
- 正文的“自动整理”折叠区域归插件维护，“人工备注”和区域外的内容由你维护。
- 更新前比较上次自动内容的摘要，包括文字、基本格式和子块标志；发现人工改动、区域删除或身份冲突会保留原文并标记待处理。
- 冲突处理：在 Notion 先把自己的修改复制到“人工备注”，再恢复自动区域至上次生成状态，随后补传。当前没有“强制覆盖”按钮；需要放弃旧自动区域时，可在停用插件后将旧页面的 `Key` 清空并保留页面，重建本地索引后重新生成。
- 网络异常后先查询页面及自动区域，不对创建请求盲目重试。旧自动区域只在新版本写入并保存本地回执后归档；清理失败时会短暂保留两个版本，补传继续恢复。
- 生成后的正文默认上传，完整原始对话不上传；来源会保留会话 ID、项目路径及原始记录位置。本机路径在手机上不能直接打开，仍可凭会话 ID 回查。
- 更新是多次 API 请求，不是 Notion 事务。同步期间请避免同时编辑自动区域；Notion API 不提供此处完整的并发编辑事务保证。

本地数据在 `$DSH_HOME/conversation-journal`（默认 `~/.dsh/conversation-journal`）。SQLite 保存脱敏后的对话索引、分批摘要、生成结果和同步回执；Token 由宿主配置管理，不写入索引或浏览器回读。常见凭据模式会先脱敏，但不保证识别所有业务敏感信息。可通过排除项目/会话限制分析范围。

旧版本的 Codex 缓存没有保存消息频道，无法仅凭索引可靠区分正文与曾误采集的推理内容；本次升级不会自动删除索引、生成结果或 Notion 页面。如果需要重新建立可信缓存，应先关闭自动整理与 Notion 同步、停止所有插件实例，备份并移走整个本地数据目录，再从原始来源重建。这样会一并重置同步回执：已有 Notion 自动区域缺少本地基线时会停止覆盖，不能把重建缓存视为自动恢复远端同步，也不能据此宣称旧远端内容已清理。没有原始来源的旧缓存应保留未知，不按正文相似度猜测和删除。

同一个 DSH_HOME 只允许一个插件实例持有索引，避免 Web 与 Desktop 同时写入。关闭插件会停止定时器、取消当前任务、释放 RPC 和索引锁；已生成内容保留。

npm run build

## 停用与卸载

关闭「每天自动整理」可仅停用定时生成；关闭「启用对话整理」会停止后续手动与自动整理，但保留结果和 Notion 连接操作。已运行的任务使用启动时配置；需要中断时在「整理」中点击「停止任务」并确认。完全卸载请在 DSH 插件管理器移除本插件并重启对应宿主：

```sh
dsh plugin --profile web remove @dsh/conversation-journal --ignore-scripts
```

移除不会删除 Notion 页面和本地缓存。需要清空本地数据时，先停用所有插件实例，再备份或移走 `$DSH_HOME/conversation-journal`。重建索引会重新分析并消耗模型用量；已有 Notion 自动区域若失去本地基线，会保守地停止覆盖。
