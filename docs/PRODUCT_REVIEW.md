# 对话整理插件：本次评审与改动

更新日期：2026-10-22。对象为 `dsh-mek-conversation-journal` 0.2.0 源码。本次根据实际交互、配置读写和索引查询路径重新评审，保留能够由代码和隔离测试支持的结论。

## 入口和设置结构

插件仍通过 DSH 的 **设置 → 对话整理** 打开。插件内部改为三个入口：

| 入口 | 用户操作 |
| --- | --- |
| 整理 | 选择日期和内容类型、开始或停止任务、查看最近生成结果 |
| 内容库 | 搜索全部结果、按日报或知识筛选、翻页、查看正文和来源、复制或导出 Markdown |
| 设置 | 配置来源与模型、自动整理、Notion 同步、隐私与高级参数 |

原先的「概览 / 生成 / Notion / 记录」混合了任务、连接配置和结果展示；模型、来源和自动计划也塞在生成流程中。现在日常整理不再需要穿过配置表单，Notion 作为可选同步目标收进设置，未连接时仍可整理和查看本机结果。

设置内使用四个分类，共用一份草稿和底部唯一保存栏。切换插件入口保留草稿；保存仅提交已变更的允许字段，空 Token 不覆盖已有凭据。模型使用宿主目录选择，保留手动填写路径。字段校验给出对应输入错误；任务或保存进行中暂停编辑，避免保存返回时抹掉后来输入。

「保存并开始整理」「保存并连接 Notion」将配置保存和后续操作串联：先校验、写入、回读确认，再执行任务。配置冲突保留草稿并停止保存，用户可显式载入最新设置并放弃当前修改。

## 确认的问题和修复

以下为此次代码中确认的缺陷，以及对应实现位置。它们不依赖真实账户数据。

| 原问题与触发路径 | 本次处理 | 实现位置 |
| --- | --- | --- |
| 选历史日期时调用设置保存，未知的 `generateDay` 被 Host 丢弃，保存回读又把日期重置为今天 | 日期作为独立任务参数保存于界面状态，选择日期不调用配置更新 | `client/index.js`：`pickDay`、`start` |
| 轮询读取新 revision，却保留旧表单；重试保存可能用新 revision 提交旧全量字段 | 编辑基线固定包含配置及 revision；仅提交差异，冲突必须显式重载 | `client/index.js`：`baseline`、`persist`；`client/settings-model.js`：`configPatch` |
| 保存期间仍可编辑，回读整表会丢失期间的新输入 | 设置表单在任务或提交期间只读，同一时刻只执行一个界面操作 | `client/index.js`：`fieldset`、`perform` |
| 列表固定读取最近 100 份，搜索只过滤这 100 份，旧记录无法找到；未同步数也只算当前列表 | 搜索进入全库查询，知识按项目和规范化标题折叠后分页；统计单独查询全库 | `host/storage.js`：`listDocumentGroups`、`documentSummary`；`host/index.js`：记录 RPC |
| 文档同步状态全局复用，换目标仍显示旧目标的「已同步」 | 同时核对当前 Notion scope、内容哈希和回执；正文改变后旧回执不再证明已同步 | `host/storage.js`：`documentRows`；`host/service.js`：`destinationScope` |
| 连接测试覆盖「最近运行」，看不到上次生成结果 | 生成任务完成、失败或停止时保存 `lastGeneration`；连接操作不覆盖它 | `host/service.js`：`settings`、`run` |
| Codex 适配器已注册即被当作来源可用，未检查目录 | 检查 Host 的 `sessions` 或 `archived_sessions` 是否存在且可读；仅说明目录可用，不代表成功读到完整内容 | `host/service.js`：`ready` |
| 最近日期计数首日按 UTC 截断，且未应用当前来源和排除范围 | 扩大查询边界后按所选时区归日，再应用来源、项目和会话过滤 | `host/service.js`：`daySummary` |
| 已排除项目或会话的旧知识仍可能被选作模型参考 | 旧知识提示同样按来源、项目及引用会话过滤；含排除引用的知识不作为参考发送 | `host/service.js`：生成流程的 `existing` 过滤 |
| Codex 的 `analysis` 也以 assistant 消息存储，原适配器仅判断角色，会把推理当正文 | 明确只保留无频道的旧格式及 `final`、`commentary` 消息；新消息记录保留频道，其他显式频道跳过 | `host/sources.js`：`codexRecord` |
| 仅选 DSH 时界面允许空 Codex 目录，但 Host 无条件拒绝，隐藏的无关字段导致无法保存 | 仅启用 Codex 来源时要求数据目录，前后端验证条件一致 | `host/config.js`：`readConfig` |
| `maxOutputTokens` 包含 Token 字样，被误报为 Notion 授权错误；RPC 错误码在前端丢失 | 保留稳定错误码，预算字段优先识别；模型、来源、配置冲突与 Notion 错误分别给出处理指引 | `host/common.js`：`errorCode`；`client/settings-model.js`：`errorGuide` |

来源计数明确标为「本地已采集记录」，不再把未扫描或旧缓存的零条记录断言为原始来源无对话。任务显示真实阶段和批次，不给出推测的剩余时间。本地生成与 Notion 同步分别显示结果，失败的同步可单独补传。

## 数据与工程边界

- 日报和知识仍由模型生成。来源 ID 校验能够排除不存在的引用，不能证明正文语义正确、确已测试或已上线；用户仍需结合来源审阅。
- 单次输入和输出预算约束一次模型调用，不能当成整个任务的费用上限。长记录分批，最多 40 批；本次没有新增费用报价功能。
- 排除范围影响后续采集、生成和旧知识提示，不自动删除此前保存的本地内容或 Notion 页面。
- 常见凭据通过规则脱敏；没有证据说明能识别所有客户信息或业务敏感数据。Token 不通过配置读取接口返回。
- 新采集跳过非用户可见的推理频道；旧索引没有保存频道，无法据此倒推并可靠净化历史缓存。必要时可先停止全部实例、备份并移走本地数据目录，再重建索引。整个目录同时包含结果和同步回执，重建会消耗模型用量，且会丢失覆盖既有 Notion 自动区域所需的本地基线；本次不自动执行清理。
- Notion 的人工修改冲突保护和写入回执保留。一次同步包含多次 API 请求，不具有完整事务或并发编辑保证。
- 插件仍嵌在宿主设置分区内。本次没有交付独立侧栏入口、生成完成通知、周报、自动知识合并或多目标同步。
